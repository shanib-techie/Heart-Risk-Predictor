About this project

A student project about applying machine learning to a healthcare-style classification problem, from raw data to a working web app.

Why I built this

I wanted to understand how machine learning applies to a real healthcare-related problem: given a person’s health measurements, can a model predict whether they have heart disease? The data is a table of health and lifestyle values with a yes/no label, has_heart_disease.

Rather than stopping at a notebook, I compared several models, kept the one that scored best, put it behind a FastAPI service, and built this interface so the model can be used and its inputs understood.

It is a learning project. It has not been clinically validated and cannot diagnose anything.

My machine learning process

The steps below are the ones that exist in the notebook and the code.

  1. Dataset

    heart_disease_risk_2026.csv: 27 columns, about 9,000 records, with has_heart_disease as the label.

  2. Data check

    I counted missing values in every column. There were none.

  3. Preprocessing

    Removed patient_id, chest_pain_type and family_history from the final feature set, then one-hot encoded sex and smoker_status. That leaves 26 model columns built from the 23 inputs the API accepts.

  4. Train and test split

    80% for training (7,200 records) and 20% for testing (1,800), with random_state=42.

  5. Four models trained

    Logistic Regression, Random Forest, XGBoost and LightGBM.

  6. Evaluation

    Accuracy and a confusion matrix for every model, plus ROC-AUC for the tree-based models.

  7. Feature importance

    I read LightGBM’s feature_importances_ to see which inputs the model relied on.

  8. Final model

    LightGBM (300 trees, learning rate 0.05, maximum depth 8), retrained on all records and saved with joblib together with its list of columns.

  9. FastAPI service

    A POST /prediction endpoint validates the input, applies the same encoding, and returns the prediction with both probabilities.

  10. This web interface

    A form that sends the 23 values to the endpoint and shows the response.

    Limitations

    • The model learns patterns in one dataset. It has not been tested on other populations or in a clinic.
    • It gives a probability, not a diagnosis, and it can be wrong in both directions.
    • The final model was trained on all records, so the scores above come from the earlier train-test experiments.
